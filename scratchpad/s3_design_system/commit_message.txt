fix(#128): render design tokens into CSS declarations the browser reads

`design_tokens.js` copies each token's raw text onto the page under its
own name. Measured in Chromium on the renderer page:

  padding: var(--SPACE_M)          -> 0px      (--SPACE_M: 16)
  border-radius: var(--RADIUS_MD)  -> 0px      (--RADIUS_MD: 12)
  transition-duration              -> 0s       (--MOTION_MEDIUM: 250)
  font-size: var(--TYPE_BODY)      -> 12px     inherited, not 13px
  color: rgba(0,255,204,51)        -> rgb(0, 255, 204)  fully opaque

Forty whole-number tokens and five rgba tints reach no stylesheet. Qt
reads the same values correctly: `rgba()` takes an alpha byte of 255,
and a Qt stylesheet needs no unit.

`src/gui/web/design_system.js` reads the table `design_tokens.js` holds
and renders each token into the CSS declaration a screen paints with:
the unit its own group implies, Qt's alpha byte as the share a browser
reads, and each shadow triple as a `box-shadow` in a colour the caller
names. It carries no token value of its own and changes no surface
value, so Qt keeps painting what it painted.

It also names a colour whose digit count Qt and a browser read apart,
publishes group order as a list, and refuses to resolve a value that
more than one name carries or that only a name of another kind carries.
