# Archetype + Multi-Agent Peer-Review Pattern

Empirically validated on Coding, GUI, and Documentation archetypes in this repository on 2026-07-24. Every archetype built to this pattern passed the same test structure. Do not deviate without a specific reason logged in the claim ledger.

## The pattern

An **archetype** is a Python class that reviews a target (file or directory) by:

1. Subprocess-invoking established third-party tools (never importing them — subprocess isolation means tool crashes don't take down the archetype).
2. Parsing each tool's output into a normalized `Finding` dataclass with fields `tool`, `severity` (critical/high/medium/low/info), `file`, `line`, `rule_id`, `message`.
3. Aggregating into an `ArchetypeReport` with:
   - `passed: bool` — True iff no critical or high findings.
   - `tool_availability: dict[str, "ok"|"missing"|"error"]` — one entry per tool, honest about what ran.
   - `errors: list[str]` — tools that failed and why.
   - `falsification: str` — required. Concrete conditions under which the report is wrong. Auto-generated by `_build_falsification()`; do NOT ship an archetype without it.
   - `findings: list[Finding]`.

A **multi-agent test** wraps the archetype with two independent Claude subagents doing judgment-only peer review of the same targets, run in parallel from a single message.

## When to build a new archetype

Trigger criteria (all four must hold):

- The domain has ≥3 established third-party tools you can subprocess-invoke.
- The tools' failure modes overlap partially so cross-verification is possible.
- Ground-truth fixtures with labeled defects can be constructed (~5-10 defects is enough).
- The domain isn't already covered by an existing archetype.

## Build order (per new archetype)

1. **Reuse the schema.** Copy `Finding` and `ArchetypeReport` from `tools/harness/coding_archetype.py`. Do not fork the schema; add domain-specific fields only if genuinely needed.
2. **Write per-tool runners** as `_run_<tool>(self, target) -> tuple[list[Finding], str]`. Return `(findings, "ok")` on success; raise `FileNotFoundError` if the tool isn't installed (the driver catches and marks `missing`).
3. **Curate severity mapping.** Establish per-rule overrides for known dangerous patterns (see `_BANDIT_SEVERITY_OVERRIDES` in coding_archetype.py). Document each entry with the reason for the override.
4. **Implement `_build_falsification()`.** Enumerate the concrete conditions under which the report is wrong (missing tools, output-format drift, target modified after review). No hand-waving.
5. **Ship a `main()` CLI.** Argparse-style `python -m tools.harness.<name>_archetype <target>` → JSON report → exit 0 if passed, 1 if failed.

## Test order (per new archetype)

1. **Two fixtures**: `known_good.<ext>` (0 ground-truth defects) and `known_bad.<ext>` (5+ labeled defects with tool-mapping notes in the module docstring, e.g., `D1 unused_import → Vulture (high)`).
2. **Run the archetype on both fixtures.** Save the JSON outputs to `<audit_dir>/raw/archetype_known_{good,bad}.json`.
3. **Assert pass gate direction**: `known_good.passed == True`, `known_bad.passed == False`. If either fails, the archetype is broken; do not proceed.
4. **Multi-agent peer review**: spawn 2 Claude subagents (`Agent(subagent_type="general-purpose")`) in a **single message** with parallel tool calls. Each receives identical prompt: judgment-only review of the same two fixtures, 500-word cap, structured JSON output. See `docs/audits/2026-07-24_gui_docs_archetypes/gui_raw/peer_reviewer_A.md` for the prompt shape.
5. **Save reviewer transcripts** to `<audit_dir>/raw/peer_reviewer_{A,B}.md` — every reviewer response, full-text, no summarization.
6. **Compare and report**: table of ground-truth × [archetype, reviewer A, reviewer B]. Compute recall per source. Save `<audit_dir>/REPORT.md` with the table plus honest documentation of what each reviewer caught that others missed.

## Non-negotiables

- **Never fabricate reviewer output** to fill a session-limit gap. If a subagent fails, say so in the report and retry after the limit resets.
- **Save every reviewer transcript verbatim.** The whole point is the operator can grep the raw output and verify.
- **Never modify the archetype to make the fixture pass.** If a defect isn't caught, log it as a known gap and add the missing rule as a separate item.
- **Log every claim.** Use `python -m tools.harness.claim_ledger log "..." --evidence "..."` before shipping any assertion. `check` gates the cascade.
- **Emit a `falsification` field.** No exceptions. Reports without falsification are unverifiable and violate the operator's show-don't-tell directive.

## Reference implementations

- `tools/harness/coding_archetype.py` — 6 tools (ruff, mypy, pyright, bandit, vulture, semgrep). 100% recall on hand-crafted fixture v2.
- `tools/harness/gui_archetype.py` — PySide6 AST + ruff + bandit. 100% recall.
- `tools/harness/docs_archetype.py` — proselint + structure + Vale (graceful missing). 80% recall (documented gap: duplicate-heading rule).

Every archetype ships with fixtures at:
- `docs/audits/2026-07-24_coding_archetype_multi_agent_test/fixtures/`
- `docs/audits/2026-07-24_gui_docs_archetypes/{gui,docs}_fixtures/`

Full REPORTs in the same audit dirs.

## Where to save the audit

Convention: `docs/audits/YYYY-MM-DD_<archetype_name>_multi_agent_test/`
```
docs/audits/YYYY-MM-DD_<name>/
├── REPORT.md
├── fixtures/
│   ├── known_good.<ext>
│   └── known_bad.<ext>
└── raw/
    ├── archetype_known_good.json
    ├── archetype_known_bad.json
    ├── peer_reviewer_A.md
    └── peer_reviewer_B.md
```

## FALSIFICATION

This SKILL is wrong if:
- Any reference implementation listed above has been deleted or moved
- The `ArchetypeReport` schema in `coding_archetype.py` no longer has the fields listed here
- The `falsification` field is missing from any of the three shipped archetypes' outputs
- The claim ledger has open claims when a cascade is attempted

Verify with:
```
python -m tools.harness.coding_archetype docs/audits/2026-07-24_coding_archetype_multi_agent_test/fixtures/known_good.py
python -m tools.harness.gui_archetype docs/audits/2026-07-24_gui_docs_archetypes/gui_fixtures/known_good_widget.py
python -m tools.harness.docs_archetype docs/audits/2026-07-24_gui_docs_archetypes/docs_fixtures/known_good.md
python -m tools.harness.claim_ledger check
```
All four should exit 0 on a clean tree.
