# Contents Rows Checked By The Archetype

**Mode: Reference.**

The manual builder checks that every contents row names the page carrying its
title. That check ran only while somebody rendered the PDF, so the same check
was hand-rolled twice on 2026-09-08. This unit makes the Docs Archetype run it
on a PDF nobody rebuilt.

## The error

The builder prints its verdict at the end of a render, and nothing else prints
it. A run of the builder over the manual on this branch reported five checks,
one of them the contents rows.

```
part numbers: ok - parts 1 to 9, contiguous
count word: ok - count word 'nine' matches 9 parts
sections present: ok - 27 listed sections present
contents pages: ok - 211 contents rows land on the page they name
no raw markup: ok - 346 pages carry no raw markup
```

## Reproduction

The Docs Archetype enumerated Markdown and text only. Pointed at a PDF it
returned one error and never looked at the file.

```
no markdown/text files at: <pdf>
```

## The cause

The builder holds its rows in memory during a render, so its check takes the
page number from the render. A PDF on disk carries the same rows as printed
text, and no function read them back.

## The correction

Three functions were added to `tools/build_product_manual.py`. The row check
itself moved into one function that both callers run.

```python
def toc_row_miss(pages: Sequence[str], text: str, page: int) -> str: ...
def read_toc_rows(pages: Sequence[str]) -> list[tuple[str, int]]: ...
def written_toc_misses(pdf_path: Path) -> tuple[int, list[str]]: ...
```

The render-time check now calls the same row function, so one implementation
serves both. The archetype gained a fourth analyzer, `contents`, which reports
one high finding per row that misses, under rule DOC006.

```
DOC006  'Alpha Section' is not on page 3, which carries 'Beta Section ...'
DOC006  'Gamma Section' names page 5 of 4
```

A PDF whose contents rows cannot be read reports the analyzer as unread, never
as clean, so an empty result cannot answer green.

```
unread: no contents rows in <name>.pdf
```

## Verification

The fixture pair sits beside the Markdown pair. The good one prints three rows
that land; the bad one prints the same document with every page number raised
by one.

```
python -m dev_harness.harness.docs_archetype harness_fixtures/docs_archetype/known_good.pdf   exit 0
python -m dev_harness.harness.docs_archetype harness_fixtures/docs_archetype/known_bad.pdf    exit 1
```

The bad fixture returns three high findings: two rows that name a page carrying
another title, and one row that names a page the document does not have.

The rule was then run on the manual PDF built from this branch. It read the
same number of rows the builder rendered, and reported the same verdict.

```
builder    contents pages: ok - 211 contents rows land on the page they name
archetype  passed true, contents ok, 211 rows read, 0 misses
```

Shifting every page number moves the count off zero in both directions, over
346 pages and 211 rows. The rows and the shifted counts below were taken
through the shipped reader, not through a copy of it.

```
shift   0    misses   0
shift  +1    misses 201
shift  -1    misses 208
shift  +2    misses 203
shift  -2    misses 209
```

A one-page PDF carrying no contents rows was reviewed as a control. The
analyzer reported unread and the report was not green.
