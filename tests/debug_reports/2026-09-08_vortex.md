## The error

Botes and Siepman (2010), as Wikipedia and StockCharts reproduce them.

```
VM+_t = |H_t - L_(t-1)|
VM-_t = |L_t - H_(t-1)|
TR_t  = max(H_t - L_t, |H_t - C_(t-1)|, |L_t - C_(t-1)|)

VI+ = sum(VM+, 14) / sum(TR, 14)
VI- = sum(VM-, 14) / sum(TR, 14)
```

The published reading of those two lines is the crossover. VI+ above VI- is a
rising market; VI- above VI+ is a falling one. Nothing in the publication turns
a high VI- into a rising reading. A VI- far above parity is the strongest
falling reading the indicator can produce.

`window_sums` at `:52` and the two divisions at `:142` and `:143` match that
exactly, and this repair does not touch them.

`src/trading/indicators/vortex.py` — `VortexIndicator.compute`, before

```python
if vim_at_ceiling:
    # Exhausted bearish momentum reads as a coming reversal, and
    # ``direction`` is overwritten to say so.
    confidence = min(1.0, max(confidence, 0.60))
    direction = SignalDirection.BULLISH
```

`VX_CEILING_PCT = 130.0` at `:28` is Acervator's own number and has no published
basis. The block above is an Acervator reading of that number, riding on the
name of a published indicator.

## Reproduction

Seventy-one recorded Coinbase tapes from `~/.acervator_ra_tablets`, read-only,
each rescaled so the last close sits at 3.1e-06 and again at 1234.0. Every
window from 36 bars in steps of 11 ran through `VotingEngine.compute_all`, and
the summary built a GateContext through the shipped `ata_gate_scan.build_context`
so the vote reaches the confidence floor the way an ATA scan reaches it. Both
chains were evaluated on all four states of the two TA-direction flags.

The pre-repair tree is a real checkout, not a copy:

```
git worktree add --detach <path> origin/current
```

The overlay is reached on the recorded data. It fires on 78 of the 3,750
readings, over 30 of the 71 tapes, with VI- between 1.3014 and 1.4859. No bar
had to be constructed.

The gate half of the instrument had to be repaired twice before it could report.

```
first build     GateContext filled by hand, confidence floor typed as 0.25
                all 30,000 verdicts False; the instrument could not report
second build    build_context, but the band position read under the wrong
                attribute name, so every row answered the 0.5 default
third build     BAND_POSITION_KEY, and the scan sentinels replaced with a
                holding that can fire; 1,314 of 30,000 verdicts True
```

The second fault is the one worth recording. `BBProximityResult` names the field
`bb_position`; the probe asked for `band_position` with a default of 0.5, so
every window read as sitting exactly on the midline. It reported a favour moving
on 78 rows that does not move at all.

## The cause

The published indicator decides a direction from VI+ against VI-, and four lines
then overwrote that decision with a different rule. The overwrite is not a
rounding error or a scale error; the two lines are exact at both price scales
and the vote they produce is discarded.

Measured on all 78 rows: separation, which is VI+ less VI-, lies between -0.9701
and -0.5214. Every one of them takes a bearish branch. Twenty take the bearish
acceleration branch at strength 1.0, fifty-eight take the bearish separation
branch at 0.6. The overwrite then republished all 78 as BULLISH.

The 0.60 strength floor beside it never bit. The bearish branches already give at
least 0.60 whenever separation is at or beyond 0.52, and the smallest separation
on the 78 is 0.5214.

## The correction

```python
if vip_at_ceiling:
    confidence = max(0.0, min(confidence, 0.45))

```

The whole `vim_at_ceiling` block comes out. Nothing outside this module reads
that flag. The five flag names appear in no other source file. The only other
occurrences anywhere in the tree are the manual page and a text sweep in
`src/core/version_sweep.py`, which reads a simulator source file that this tree
does not contain. The overlay therefore has no reader to keep working, and it
does not move to an indicator of its own.

The four flags are still published beside the vote, so the panel can show that a
line is saturated. What is gone is the vote saying the opposite of what the lines
say.

The ceiling that touches strength only is untouched. `vip_at_ceiling` caps a
bullish vote at 0.45 and never changes a direction, so it does not contradict the
published reading. Botes and Siepman publish no strength scale at all, so there
is nothing for it to depart from.


Every branch inside `compute` tests the number it computed, so no vote and no
gate ever read the cut copy. The panel's hover cell prints three decimals and was
handed a number carrying four.

### Every reader

Seven parts of the platform read this indicator.

| reader | on a VI- at or above 1.30 |
| --- | --- |
| the panel's consensus | one vote moves from rising to falling; moved on 78 of 3,750 |
| `indicator_panel.py` cell | the arrow turns from up to down |
| `indicator_panel_surface.py` cell | the arrow turns from up to down |
| `ata_spm.py` sentence | prints separation to four decimals; unchanged on all 3,750 |
| `ta_invariants.py` bound | `_nonneg("vi_plus")` and `_nonneg("vi_minus")`; unchanged |
| `ta_engine.py` recorder | records the vote it now casts |
| `scrumming_bot.py` position boost | never reached these rows |

`native_chart.py` names this voter to drive an overlay toggle and draws both
lines from `VortexIndicator.lines`, which this repair does not touch.

The position boost is the one reader the overwrite could have reached and did
not. `ScrummingBot.tick` pays a bullish Vortex +0.12 at the upper band above 0.75
and takes -0.05 back in the middle zone 0.35 to 0.65; `ata_gate_scan.vortex_favour`
answers the same. On all 78 ceiling rows the band position sits between -0.1341
and 0.2238, below both zones, so the favour is zero before and after. A saturating
downward line means the price has already fallen hard, which puts it at the bottom
of the band, which is where that boost pays nothing.
