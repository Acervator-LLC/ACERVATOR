## The error

Wilder, *New Concepts in Technical Trading Systems* (1978), reproduced by
StockCharts on the ADX page:

```
+DM_t  = H_t - H_(t-1)   when it exceeds L_(t-1) - L_t and 0
-DM_t  = L_(t-1) - L_t   when it exceeds H_t - H_(t-1) and 0
+DI    = 100 * Wilder(+DM, 14) / Wilder(TR, 14)
-DI    = 100 * Wilder(-DM, 14) / Wilder(TR, 14)
DX     = 100 * |+DI - -DI| / (+DI + -DI)
ADX    = Wilder(DX, 14)
```

`ADXIndicator.compute` computes exactly that. Two counts follow from it. The
smoothing needs `period` true ranges before it produces a value, so the first
DX lands on bar 15. The ADX is the average of `period` DX values, so the first
ADX lands on bar 28. Twenty-eight bars, and not one more.

`src/trading/indicators/adx.py` — the guard, before

```python
n = len(candles)
if n < self.period * 2 + 2:
```

`git log -S` traces the `+ 2` to `be6aa048`, the initial upload. No commit,
comment or docstring states a reason for it. Every sibling indicator's guard is
the count its own maths needs: `atr.py` and `rsi.py` ask for `period + 1`,
`vortex.py` for `period + 1`, `bollinger.py` for `period`.

Two consequences, both measured below.

**The vote.** On windows of 28 and 29 bars the ADX exists and the module
abstained. `GateContext.adx` documents `0.0` as the not-populated sentinel and
`ADXTrendSuppressionGate` passes on it, so the scrum chain fired on two bars
where a real ADX would have blocked it.

**The previous reading.** `_wilder_smooth` writes `period - 1` zeros ahead of
its first real value. `p_adx = s_dx[-2]` read one of those zeros on the first
ADX bar, so `adx_rising` was decided against padding.

A third departure sits beside them. The reading the module published was cut to
two decimals.

`src/trading/indicators/adx.py` — the reading, before

```python
details={
    "adx": round(adx, 2),
    "di_plus": round(di_plus, 2),
    "di_minus": round(di_minus, 2),
```

## The cause

`self.period * 2 + 2` asks for two bars that Wilder's ADX does not need, and
`s_dx[-2]` reads the smoothing's own zero padding on the bar where the first
ADX lands. `round(adx, 2)` quantises the published reading to steps of 0.01,
and three parts of the platform build a gate input from that copy.

## The correction

The guard asks for the bar count the maths needs, the previous reading starts
where the padding ends, and the reading carries what the module computed.

`src/trading/indicators/adx.py` — after

```python
n = len(candles)
# period bars seed the smoothed TR, and period DX values seed the ADX.
if n < self.period * 2:
```

```python
adx_values = s_dx[self.period - 1 :]
adx = adx_values[-1] if adx_values else 0.0
p_adx = adx_values[-2] if len(adx_values) >= 2 else adx
```

```python
details={
    "adx": adx,
    "di_plus": di_plus,
    "di_minus": di_minus,
```

The zero-denominator contract is unchanged and is now stated where it is made.
A true range is a maximum of differences between equal prices on a halt, so the
smoothed value cancels to exactly `0.0` and the test is exact at every price
scale.

`src/trading/indicators/adx.py` — the abstention that stays

```python
# s_tr[-1] reaches 0.0 only on a halted window, where DI is 0/0 and
# adx abstains.
if not s_tr or s_tr[-1] <= 0.0:
```

One reader printed the published number with no format of its own, so the bot
log grew a seventeen-digit ADX. It now cuts a decimal reading to four places.

`src/trading/scrumming/snapshots.py` — the bot log cell

```python
reading = cell.get("detail")
if reading is not None:
    shown = f"{reading:.4f}" if isinstance(reading, float) else reading
    text = f"{text} ({cell['detail_key']} {shown})"
```
