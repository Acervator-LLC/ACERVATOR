## 2 - The Electron shell would not start under this session's environment

### 2.1 the error

```
Error: Cannot find module 'electron'
Require stack:
- .../wt-u62/desktop/main.js
    at Module._resolveFilename (node:internal/modules/cjs/loader:1571:15)
    ...
  code: 'MODULE_NOT_FOUND'
```

### 2.2 reproduction

```
electron.exe <worktree>/desktop --remote-debugging-port=9334
```

### 2.3 the cause

`ELECTRON_RUN_AS_NODE=1` is set in this session's environment. It makes `electron.exe`
run `desktop/main.js` as plain Node, where `require("electron")` resolves through
`node_modules` instead of the built-in module. Adding `NODE_PATH` made it worse: the
require then resolved to the npm wrapper, whose export is a path string, and `main.js`
raised `TypeError: Cannot read properties of undefined (reading 'whenReady')`.

### 2.4 the correction

The reading script deletes `ELECTRON_RUN_AS_NODE` from the environment it spawns the
shell with. No product file was involved.

### 2.5 the rerun


## 3 - A screenshot of the encounter state never returned

### 3.1 the error

No traceback. `Page.captureScreenshot` sent over the devtools protocol did not answer
for eleven minutes while the same call had answered twice in the same run. The last file
written was timestamped 20:34:21 and the clock read 20:45:37 with the shell's four
processes still resident.

```
react_normal_resting.png    20:34:14   written
react_narrow_resting.png    20:34:15   written
react_normal_encounter.json 20:34:21   written
react_normal_encounter.png             never written
```

### 3.2 reproduction

Fire the grade control on the demo chain so the right half draws the encounter, then ask
for a screenshot.

### 3.3 the cause

The encounter region declared `container-type: size` and sized the enemy slot inside it
with `width: min(100cqh, 100cqw)`. The region is a grid whose second track is `auto`, so
that track's width came from the slot, the slot's width read `100cqw` off the region, and
the region's width came from the track. Reading the container's inline size from a child
that the container's own `auto` track is sized by is circular, and layout did not settle.

### 3.4 the correction

The slot squares off the region's block size alone, which the top row fixes and the track
sizing does not touch, and a plain percentage keeps it inside a region narrower than it is
tall.

```css
.acervator-poa-tab [data-part="enemy-slot"] {
  width: 100cqh;
  height: 100cqh;
  max-width: 100%;
}
```

### 3.5 the rerun

All five readings and all five screenshots written, node exit 0.

