# The PoA seam audit — what each tool printed

Reference. This unit changed no behaviour. Nothing under `src/` was edited, so no
correction appears below and the section says so rather than inventing one.

Subjects: the twenty-three modules of `src/competition/`, `src/gui/shared_testnet.py`,
`src/gui/main_tabs/proof_of_accumulation_tab_surface.py`, and the five Solidity
files under `contracts/` that hold a figure one of those modules also holds.

The findings are in
[`docs/engineering-notes/2026-09-10_poa_seam_audit.md`](../../docs/engineering-notes/2026-09-10_poa_seam_audit.md).

## The error

No program raised. `vulture` and `git grep` reported, and one method of the
running code was driven to read what it answers.

The audit's own first reading was a false zero, and that is the error worth
recording.

```
python -m vulture src/competition/ src/gui/shared_testnet.py
    exit 0
    zero lines
```

An unused function carries 60% confidence in `vulture`, and `pyproject.toml`
line 303 sets `min_confidence = 70`. At that floor no uncalled function can ever
be reported, so the empty output was a fact about the setting.

```
pyproject.toml:294  [tool.vulture]
pyproject.toml:303  min_confidence = 70
dev_harness/harness/coding_archetype.py:794  "--min-confidence", "60"
```

The archetype passes 60 on the command line. Reading the archetype is what found
the floor.

## What the instrument cannot report, measured

`vulture` matches a bare name against every name used anywhere in its scope, so a
method whose name is also used elsewhere is cleared wherever it appears. Two
seams were invisible for that reason and were found with `git grep`.

```
attach_to_bus     src/core/logging_engine.py:502 defines one and main.py:627
                  calls it, so src/competition/certification_socket.py:474 is
                  never reported
capture_bounds    a parameter of that name at src/competition/certification_socket.py:199,
                  src/gui/shared_testnet.py:495 and :512 clears the property at
                  src/gui/shared_testnet.py:402
```

Both were confirmed by counting occurrences over the index rather than the
working directory.

```
git grep -o "\battach_to_bus\b" -- src/ main.py tools/ contracts/ | wc -l
    10, split across three files; two of them are the socket's def and its docstring

git grep -l "_market_rotation" -- src/ main.py tools/
    src/gui/shared_testnet.py
```

Eight of the ten objects `SharedTestnetBridge.install_on` attaches answer that
second command with the bridge file alone.

```
_quint_ledger  _market_rotation  _capture_bounds  _certification_socket
_node_link  _action_spend  _event_redistribution  _poa_world
```

## The cause, for the one seam driven rather than read

`src/gui/main_tabs/proof_of_accumulation_tab_surface.py:1311` answers the season
every control keys on.

```
def chain_season() -> int:
    return int(LocalTestnet().get_competition_stats()["current_season"])
```

`LocalTestnet.__init__` at `src/competition/local_testnet.py:811` builds a new
`LocalChain()` and a new `LocalRegistry`, and takes a persistence path only when
one is passed. None is passed here.

Driven through the real method:

```
python -X dev -c "from src.competition.local_testnet import LocalTestnet; s=LocalTestnet().get_competition_stats(); print('block_number', s['block_number']); print('current_season', s['current_season']); print('total_competitions', s['total_competitions'])"

    block_number 0
    current_season 1
    total_competitions 0
```

`src/competition/local_testnet.py:594` sets `_current_season = 1`, and the index
holds no other statement that writes it.

```
git grep -n "_current_season" -- src/ main.py tools/
    src/competition/local_testnet.py:594         self._current_season = 1
    src/competition/local_testnet.py:921   "current_season": self._registry._current_season,
```

`src/gui/main_tabs/proof_of_accumulation_tab_surface.py:1304` builds the tab's
`MarketRotation` over the same fresh chain, and
`src/competition/market_rotation.py:525` sends the rotation commitment to it.

```
chain = self._testnet.chain
tx = chain.send_tx(exchange_id, ROTATION_CONTRACT, COMMIT_FUNCTION, args)
chain.emit(tx.tx_hash, ROTATION_CONTRACT, COMMITTED_EVENT, args)
```

`src/gui/shared_testnet.py:354` builds the same object over the chain that loads
from disk. Nothing reads that one.
