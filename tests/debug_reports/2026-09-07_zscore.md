# Z-Score: the two spellings, and the AlgoPoint upgrade

Two halves, measured separately. Half one repairs the formula. Half two builds
the published upgrade on top of the repaired formula, so a moved reading can be
traced to one of them and not to both at once.

Every run used a throwaway home. `~/.acervator/settings.json` hashed the same
before and after:

```

after   f366f42f0e49b4b3468f301b4f2f701669cc13005cfe1ebac7a56988ec376423
```

## Half one — one quantity, two spellings

**The error.** The same score was written twice, once for the current bar and
once for the bar before it, and the two spellings did not agree. The second one
added a small constant to the divider, which changes every ordinary reading and
guards nothing, because the check above it had already refused the only case
that needed guarding.

**Reproduction.** A tape of 52 bars whose window has a deviation of exactly two
billionths, with the last-but-one close sitting exactly two deviations above the
mean. The published formula gives 2.000. The same shape was run again at a
four-figure price, where the added constant is far too small to matter.

The pre-repair code is a real checkout, not a copy:

```
git worktree add --detach <path> b27c6cd^
```

**The readings.**

| Tree | BONK 3.1e-06, deviation 2e-9 | four-figure price |
| --- | --- | --- |
| pre-repair | z_prev **1.333** | z_prev 2.000 |
| this branch | z_prev **2.000** | z_prev 2.000 |

The four-figure reading is 2.000 in both trees. The defect only appears where the
prices are small, which is where the operator trades, and the same run reports a
difference between the two price scales when there is one.

**The correction.** One function computes the mean, the deviation and the score,
and returns nothing at all when the window has no range. Both readers call it,
so a second spelling cannot exist.

`src/trading/indicators/zscore.py` — the only division

```python
def _window_zscore(closes: list, close: float) -> Optional[tuple]:
    if _window_has_no_range(closes):
        return None
    count = len(closes)
    mean = sum(closes) / count
    deviation = (sum((c - mean) ** 2 for c in closes) / count) ** 0.5
    return mean, deviation, (close - mean) / deviation
```

The abstention is now a refusal to answer rather than a quietly shifted number.

## Half two — Z-Score Predictive Zones

**What the page publishes.** Two formulae, four settings by name, and a stated
noise reduction. The score is smoothed by a volume weighted average, turning
points are found in that smoothed series and kept only when they reach a minimum
score, the last few of each side are averaged, and each average is turned back
into a price.

```
Z               = (Price - Mean) / Standard Deviation
Projected Price = Mean + (Target Z * Standard Deviation)
```

**What it does not publish.** No default value for any of the four settings, and
no source code on the page. Three settings take a number already in this file or
quoted on the page itself; the fourth is chosen here and is marked as chosen in
the manual. Nothing was invented to fill a formula.

**Reproduction.** Three hundred bars drifting around the base price with a
two-bar excursion every thirty-seven, alternating sign so the score carries both
peaks and troughs past the minimum. Volume moves on its own cycle so the
smoothing weights unequal bars. Run at BONK scale and again at a four-figure
price.

## The ATA-SMP message

The message wording names the fields it explains, and the upgrade publishes
fields it did not name. With the wording left alone the post still reads, but
says nothing about the zones:

```
Z-Score: z-score +0.340. Votes neutral at 0% confidence.
```

With the wording naming the two zone prices, read back from the real message
builder:

```
Z-Score: z-score +0.340, predictive zone 3.05314e-06 to 3.17414e-06. Votes
neutral at 0% confidence.
```

Both zone prices are published on every reading, including before any turning
point has been remembered, so the wording can name them without ever falling
back to its no-reading text.

## What did not move

The twelve voters are hashed over one tape by a canonized test, direction,
confidence, weight and every detail field included. Eleven are bit-identical and
only the Z-Score moved, which is what a single-indicator repair must look like:

```
Differing items:
{'zscore': '854c3493369b0bbf'} != {'zscore': 'f13d4d992ca85e24'}
Omitting 11 identical items
```

Three pinned digests moved with it and were re-pinned in this same change, which
is what those pins ask for when a published formula is corrected.

## Left in place, deliberately

The manual still carries the operator's line saying the upgrade is still to come,
and still quotes the two divisions as separate blocks. Both are now out of date.
His words are his to retire, so every manual change here is an addition and
nothing was reworded.

The deviation is published rounded to six decimal places, so at BONK scale it
prints as zero while the score is computed from the full value. No arithmetic
reads the rounded copy. Changing it would change a number on his screen, so it
is named here and not touched.
