## The error

Appel, as StockCharts reproduces him on the MACD page:

```
MACD Line      = 12-day EMA - 26-day EMA
Signal Line    = 9-day EMA of the MACD Line
MACD Histogram = MACD Line - Signal Line
```

`MACD._lines` computes exactly that and is untouched. All three values are
prices, and the published reading quantised each one to a fixed step of 1e-06.

`src/trading/indicators/macd.py` — the reading, before

```python
details={
    "macd_line": round(curr_macd, 6),
    "signal_line": round(curr_signal, 6),
    "histogram": round(curr_hist, 6),
```

At a last close of 3.1e-06 the MACD line runs at 1e-08, two orders below that
step, so all three fields round to `0.0`. At a four-figure price the same market
shape publishes real numbers. One threshold serves the whole fleet, and this is
the same structure reading differently on two assets.

A second departure sits beside it. `MACD.compute` divides by
`abs(closes[-1]) * 0.001` with no test on that denominator. `candles_from_raw`
refuses a close at or below 0.0, but `compute` takes a `Candle` list and
`src/gui/indicator_panel.py:1583` builds one directly. A close of 0.0 raises
`ZeroDivisionError` out of `VotingEngine.compute_all`, which kills every other
voter in that run.

A third sits one layer out. `ta_invariants.INDICATORS["macd"]` bounded the three
fields with a tolerance of `2e-6`, chosen for the rounding above. At BONK's
scale that slack is wider than any real MACD, so the bound could not report.

## Reproduction

Seventy-one recorded Coinbase tapes from `~/.acervator_ra_tablets`, read-only,
each rescaled so the last close sits at 3.1e-06 and again at 1234.0. Every
window from 36 bars in steps of 11 ran through `VotingEngine().compute_all`, and
the summary built a `GateContext` whose other fields all pass. The chains are
the real ones, `build_scrumming_scrum_chain()` and `build_scrumming_fold_chain()`,
evaluated on both states of the TA-direction flags.

## The cause

`round(x, 6)` is an absolute decimal step applied to a price-scaled quantity, so
what survives it depends on the price. The confidence divides a price by a
price and is scale-free; the reading is not, and five parts of the platform read
the reading rather than the vote.

`abs(closes[-1]) * 0.001` is written out four times and tested nowhere, so the
one input that makes it zero reaches a division.

The `2e-6` tolerance was calibrated around the rounding, not around the maths.

## The correction

The reading carries what the module computed, the two denominators have names
and a test, and the bound is exact.

`src/trading/indicators/macd.py` — after

```python
crossover_scale = abs(closes[-1]) * 0.001
momentum_scale = abs(closes[-1]) * 0.002
if crossover_scale == 0.0 or momentum_scale == 0.0:
    # No scale to divide by, so macd publishes no confidence here.
    return Signal(
        "macd",
        timeframe,
        SignalDirection.NEUTRAL,
        0.0,
        self.weight,
        abstained=True,
    )
```

```python
details={
    "macd_line": curr_macd,
    "signal_line": curr_signal,
    "histogram": curr_hist,
```

Appel publishes no confidence formula, so none is invented here. The existing
normaliser stays and its domain is closed: where the denominator is zero the
module abstains, which is what `adx.py`, `kaufman_er.py` and `zscore.py` each do
at their own zero denominator.

`src/trading/ta_invariants.py` — after

```python
lambda d: float(d["histogram"])
== float(d["macd_line"]) - float(d["signal_line"]),
```

`MACD._lines` builds the histogram as `m - g` from the same two doubles the
reading carries, so the difference cancels bit for bit and the test is exact.

One reader printed a price to six decimal places, so it printed zeros on a
micro-priced market. It now prints eight significant figures.

`src/trading/ata_spm.py` — the ATA-SMP sentence

```python
"macd": ("MACD", ("histogram",), "histogram {value:+.8g}"),
```
