## The error

Wilder (1978), as StockCharts ChartSchool and Investopedia reproduce him.

```
gain_t  = max(C_t - C_(t-1), 0)
loss_t  = max(C_(t-1) - C_t, 0)
AvgGain = Wilder(gain, 14)
AvgLoss = Wilder(loss, 14)
RS      = AvgGain / AvgLoss
RSI     = 100 - 100 / (1 + RS)
```

One quantity. Above 70 is overbought, below 30 is oversold, and the same number
decides the label and the reading. Nothing in the publication produces a second
copy of it.

`src/trading/indicators/rsi.py` — `RSIIndicator._compute_metrics`, before

```python
return {
    "rsi": round(rsi, 2),
    "rs_indeterminate": rs_indeterminate,
    "overbought": rsi > 70,
    "oversold": rsi < 30,
```

`compute` then reads `metrics["rsi"]`, which is the cut copy, and tests it
against 70 and 30, computes `dist` from it, and republishes it in
`Signal.details`. The two flags beside it were computed from the uncut local.

The recursion at `:55` and `:56` and the two branches at `:58` to `:63` are
Wilder exactly, and this repair does not touch them.

**The disagreement window is 0.005 wide.** `round(v, 2)` maps every value in
(70.000, 70.005) to 70.0, and 70.0 is not above 70. The mirror window is
(29.995, 30.000), which rounds up to 30.0, and 30.0 is not below 30. Inside
either window the label fires and the vote does not.

## Reproduction

Seventy-one recorded Coinbase tapes from `~/.acervator_ra_tablets`, read-only,
each rescaled so the last close sits at 3.1e-06 and again at 1234.0. Every
window from 36 bars in steps of 11 ran through `VotingEngine.compute_all`, and
the summary built a GateContext through the shipped `ata_gate_scan.build_context`
so the vote reaches the confidence floor the way an ATA scan reaches it. Both
chains were evaluated on all four states of the two TA-direction flags.

The pre-repair tree is a real checkout, not a copy:

```
git worktree add --detach <path> origin/current
```

**No recorded reading lands in either window.** The closest reading to 70 is
70.06, already voting bearish; the closest to 30 is 29.97, already voting
bullish. Over 3,750 readings the index ran from 12.6 to 89.45, so a window
0.005 wide is expected to catch about a quarter of one reading. It caught none.

The bar was therefore constructed, and the construction is a real tape plus one
bar. Take a recorded prefix, ask what final close puts the index at 70.003, and
bisect on the real `_compute_metrics` until it does. **All 2,901 prefixes of 40
bars or more admit such a close**, because the index rises with the final close
over that range.

```

    prefixes attempted                              2,901
    prefixes reaching 70.000 to 70.005              2,901
    the final bar each one needs
        smallest                                  +0.0049%
        median                                      25.70%
        largest                                    334.53%
        needing 1% or less                              72
        needing 5% or less                             272
```

Most of those bars are large, because most windows sit a long way from 70. The
smallest is the one to read. `LINK_1d_2023_coinbase.json`, 271 real bars,
previous close 7.81, and a final close of 7.810380394093077 — an up bar of half
a basis point. That is an ordinary tick on a market that has already run to the
70 line, not a manufactured shock.

The gate half of the run had to be repaired before it could report. The first
build filled the context from `build_context` alone and all 30,000 verdicts read
False, because the six `POSITION_BOUND_GATES` carry scan sentinels — no surplus,
no fold queue, no hysteresis reference — and a scan holds nothing for them to
test. Replacing those six with a holding that can fire brings 1,322 of the
30,000 to True.

## The cause

`_compute_metrics` publishes the index cut to two decimals and labels the bar
from the uncut number. `compute` reads the cut copy for the direction test, for
the distance that sets the strength, and for the detail it republishes. One
quantity leaves the module as two values, and at the threshold they disagree.

Measured at the frame, on the constructed LINK window at 3.1e-06, entered the
way a bot tick enters it:

True and the branch is False.

## The correction

`src/trading/indicators/rsi.py` — `RSIIndicator._compute_metrics`, after

```python
return {
    "rsi": rsi,
    "rs_indeterminate": rs_indeterminate,
    "overbought": rsi > 70,
    "oversold": rsi < 30,
```

The cut is gone. One number leaves the module, and the label, the vote, the
strength and the published reading all read it. The rounding belonged to a
display, and every display that needs it already applies its own: `ata_spm.py`
prints two decimals and `indicator_panel.py` prints three.

Two sentences that named a reader which does not exist came out with it. The
module docstring said the series is one "a chart draws" and line 84 said "the
chart overlay reads these". `rsi_series` appears in no other file in the tree,
and `_compute_metrics` has one caller, `compute`, which does not republish it.
The series stays; the claim about a chart does not.

The thresholds are untouched. Both sites already tested `> 70` and `< 30` with
the same operator, so one value is the whole repair.

### What is not repaired here

Issue #414 item 6 names two dead-weight epsilons, in `ichimoku.py` and
`supertrend.py`. Neither is in this file and neither is touched.

One finding outside this file came out of the gate sweep and is named on the
issue rather than repaired here. `src/trading/indicators/bollinger.py` at `:147`
to `:149` publishes `upper`, `middle` and `lower` as `round(price, 6)`. At
3.1e-06 six decimal places quantize all three to the same number, so the band
half-span is exactly 0.0. `ata_gate_scan.band_of` reads those three fields and
`ramp_step` divides by that span, clamped by `BAND_SPAN_FLOOR = 1e-12`.

```
DOT 2023, 342 bars, band half-span over the ramp walk
    3.1e-06     323 windows, smallest 0.0, 241 under the 1e-12 floor
    1234.0      323 windows, smallest 21.2336, 0 under the floor
```

That is the same shape as this item — a rounded copy reaching a consumer — in a
different indicator and a different consumer, and it silences `target_fires` at
BONK's scale. It belongs to a `bollinger` unit, not to this one.
